# StickS3 QEMU: first functional peripheral milestone

**Experimental emulator-only code. Do not flash this probe.** Production firmware,
physical USB ownership, and the running bridge are unchanged.

This is a functional firmware-interface prototype, not a complete StickS3 board or
a timing-calibrated simulator. It deliberately starts below Arduino/M5Unified.

## Numeral accommodation — no calibration

The [width-aware layout](../../docs/avatar-counter-space.md) shifts/shrinks the
avatar only beside SIDE labels. Bottom numerals use normal-size fonts and grow
inward, reducing fonts only for genuine combined-width collisions; the avatar
stays full-size and centred. Sorting reserves old/new widths jointly and keeps
the whole unequal pair on screen. All 25 native/76 Python/16 QEMU functional
cases and normal O2 compilation pass.
`test_counter_labels.cpp` rejects actual new source/app hashes and old binaries
paired with that source. Larger bottom glyphs change raster workload, not
historical occupancy tables, FIFO costs or emulator clocks. No physical FPS or
full-production GDMA/board-init/PSRAM execution is claimed.

## Continuity director — no new calibration

The shared production transition director adds notice/respond/settle,
interruptible doze/wake and recovery acting. See
[continuity integration](../../docs/avatar-continuity.md). Native tests cover
all directed state edges, three cadences and wrap, plus explicit rejection of
changed source/binary/transition layouts by the historical occupancy selector.
FIFO packet costs, emulator clocks and full-production GDMA/board-init/PSRAM
gates are unchanged. Synthetic galleries are not physical/QEMU FPS evidence.

## Shoulder junction — no calibration

The mirrored completed-only left / active-only right retreat correction is in
[shoulder-junction evidence](../../docs/avatar-shoulder-join.md). It changes
only decorative mask joins/contact bounds and skips the zero-weight vertical
contact component at exactly zero corner reflow. It does not change animation,
transport, USB or CPU clocks. Existing unknown-source/layout rejection and FIFO

full-production GDMA/board-init/PSRAM execution is still a separate gate.

## Verified

The initial complete run passed **10/10 tests, no skips**, using:

- Espressif QEMU `esp-develop-9.2.2-20260417`, commit
  `40edccac415693c5130f91c01d84176ae6008566` plus `qemu-sticks3.patch`;
- ESP-IDF v5.5.1, Xtensa GCC `esp-14.2.0_20241119`;
- a file-backed 8MiB flash image and local Unix sockets; no physical device.

Nine qtests drive actual emulated MMIO. One **separate TCG guest boot** uses the
stock ESP-IDF SPI master, ST7789 panel, and USB Serial/JTAG drivers:

1. Boot the ROM, bootloader, FreeRTOS, and application.
2. Initialize SPI3 at a requested 40MHz with **DMA disabled**.
3. Use the stock panel driver to draw all 32,400 pixels at 240×135. The driver
   splits the 64,800 RGB565 bytes into PIO transactions. The host compares every
   screenshot pixel against the independently generated RGB reference.
4. Read `C|2|1|3\n` through the stock USB driver's interrupt/RX path.
5. Send the production-shaped seven-byte `S3V1A\x00\x0a` header and 2,560 generated
   bytes through its interrupt/TX path and 256-byte software ring. The host checks
   all 2,567 bytes exactly. **These are generated bytes, not microphone audio.**

The IDF API submits a whole ring item, so the guest sends payload pieces of at
most 128 bytes. This is not a test of Arduino `HWCDC::write()` or production
`sendFrame()` short-write handling. ROM boot text appears on CDC even with the
SDK's secondary console disabled; the test drains it before requesting a frame.

The qtests cover portrait/landscape frame coverage, D/C, manual CS, a pixel split
across transactions/CS boundaries, hardware reset, sleep/display-off, SPI UPDATE,
completion/IRQ W1C, unsupported DMA failure, USB 64-byte and short packets,
binary integrity, RX backpressure, disconnect/SOF freeze/reconnect, and interrupt
matrix active-source rerouting and shared-level OR behavior.

## What the patch does

- Adds opt-in `-machine esp32s3,stick-lcd=on` and a `stick-lcd` graphical console.
  The existing generic RGB console remains separate. Screenshot commands must
  select **device `stick-lcd`**, not the default console.
- Maps a limited GPSPI3 controller at `0x60025000`, with a 64-byte PIO FIFO,
  byte-aligned command/address/MOSI phases, guest clock divider, virtual-clock
  completion, and the SPI3 interrupt source.
- Embeds a limited ST7789 logical RAM/controller model: 240×320 controller RAM,
  a source-derived 135×240 crop at (52,40), RGB565, address windows, RAMWR/RAMWRC,
  MADCTL, COLMOD, reset, sleep, and display on/off. MV swaps the console to
  240×135. Optical inversion, power/gamma, TE and scanout are not simulated.
- Adds GPIO output-latch/W1TS/W1TC storage and fixed D/C45, reset21 and manual-CS41
  wiring. **Pad enable/tristate, GPIO matrix, input/pulls and GPIO edge IRQs are
  not modeled.** This is not a general-purpose pin-level SPI bus.
- Replaces the USB Serial/JTAG stub with 64-byte TX/RX FIFOs, packet flush/full
  behavior, raw/masked/enable/clear interrupt state, frame index/SOF, and a local
  chardev backend. Connect/disconnect and socket backpressure are functional.
- Fixes the S3 interrupt matrix to retain source levels, reroute already asserted
  inputs, and OR shared inputs instead of letting a low source cancel another.
  **This fix was required by the unmodified SPI driver:** it unmasks/reroutes a
  transaction-done interrupt that is already asserted to start queued work.

The USB backend is **not host USB enumeration, USB/IP, libusb passthrough, JTAG,
CRC/retry PHY simulation, or a physical `/dev/ttyACM*` device**. The default
`poll-us=1000` services at most one pending IN packet and advances the modeled SOF
frame once per poll. Other values are uncalibrated synthetic stress settings,
not valid physical USB frame periods. Socket buffering is not a USB host
controller's real transfer schedule.

SPI completion assumes an 80MHz peripheral source divided by the programmed
clock register. The exact qtest deadline validates that formula, not real ESP32
CPU/cache/PSRAM/SPI timing. Bytes are interpreted at transaction completion, not
clocked on virtual wires bit by bit. Do not use host test duration as device FPS.

No octal PSRAM, SPI3 GDMA, M5PM1/BMI270/I2C board-init dependencies, buttons,
backlight/power rails, I2S/ES8311, audio, or migration support was added. The
complete unmodified Arduino/M5Unified dashboard and bridge have **not** run here.

## Reproduce the QEMU build

Apply only to the pinned source in a separate checkout; do not overwrite a
system QEMU installation. Source additions in the patch retain QEMU's GPL license.

```sh
REPO=/path/to/stick-s3          # this repository
LAB=/path/to/scratch/qemu-lab    # any scratch directory outside the repository
git -C "$LAB/qemu-source" rev-parse HEAD  # must match the commit above
git -C "$LAB/qemu-source" apply --check "$REPO/experiments/qemu-sticks3/qemu-sticks3.patch"
git -C "$LAB/qemu-source" apply "$REPO/experiments/qemu-sticks3/qemu-sticks3.patch"
```

Install build dependencies normally, or extract development/runtime packages
without system installation (for example `apt download` plus `dpkg-deb -x`
under `$LAB/qemu-deps`) for `libgcrypt20-dev`, `libgcrypt20`, `libgpg-error-dev`,
`libgpg-error0`, `libslirp-dev` and `libslirp0`. GCC, Ninja, GLib, Pixman and PNG
development files are also needed.

```sh
mkdir -p "$LAB/qemu-build"
cd "$LAB/qemu-build"
PKG_CONFIG_PATH="$LAB/qemu-deps/usr/lib/x86_64-linux-gnu/pkgconfig" \
  "$LAB/qemu-source/configure" \
  --target-list=xtensa-softmmu --disable-docs --disable-werror \
  --enable-slirp --enable-gcrypt --disable-gtk --disable-sdl \
  --disable-opengl --disable-curses --disable-capstone --disable-tools \
  --disable-user --disable-rust \
  --extra-cflags="-Wno-error=discarded-qualifiers -I$LAB/qemu-deps/usr/include -I$LAB/qemu-deps/usr/include/slirp -I$LAB/qemu-deps/usr/include/x86_64-linux-gnu" \
  --extra-ldflags="-L$LAB/qemu-deps/usr/lib/x86_64-linux-gnu"
ninja -j6 qemu-system-xtensa
```

The discarded-qualifiers exception is a host-toolchain compatibility workaround
for unchanged upstream QEMU/dtc sources. Gcrypt and Slirp must be available to
this Espressif build; disabling them did not avoid all dependent sources.

## Build the isolated stock-driver guest

Use an installed ESP-IDF v5.5.1 environment. Its `export.sh` demands extra
GDB/ULP/OpenOCD tools; a minimal environment without them works like this:

```sh
export IDF_PATH="$LAB/esp-idf"
export IDF_TOOLS_PATH="$LAB/idf-tools"
export IDF_PYTHON_ENV_PATH="$LAB/idf-venv"
export PATH="$IDF_PYTHON_ENV_PATH/bin:$IDF_PATH/tools:$IDF_TOOLS_PATH/tools/xtensa-esp-elf/esp-14.2.0_20241119/xtensa-esp-elf/bin:$PATH"
python "$IDF_PATH/tools/idf.py" \
  -C "$REPO/experiments/qemu-sticks3/probe" \
  -B "$LAB/peripheral-probe-build" \
  -D SDKCONFIG="$LAB/peripheral-probe-build/sdkconfig" \
  -D IDF_TARGET=esp32s3 build
```

The default partition table and **no PSRAM** are intentional probe constraints,
not a production StickS3 configuration. CMake's optional ROM/GDB-init warning is
not a firmware build failure. Never execute the flash commands printed by IDF.

Generate a regular file image from the build's actual offsets:

```sh
export STICKS3_PROBE_BUILD="$LAB/peripheral-probe-build"
python3 - <<'PY'
import json, os
from pathlib import Path
build = Path(os.environ['STICKS3_PROBE_BUILD']).resolve()
image = bytearray(b'\xff' * (8 * 1024 * 1024))
previous_end = 0
files = json.loads((build / 'flasher_args.json').read_text())['flash_files']
for offset, name in sorted(files.items(), key=lambda pair: int(pair[0], 0)):
    offset = int(offset, 0)
    source = (build / name).resolve()
    assert source.is_relative_to(build) and source.is_file()
    contents = source.read_bytes()
    assert previous_end <= offset and offset + len(contents) <= len(image)
    image[offset:offset + len(contents)] = contents
    previous_end = offset + len(contents)
output = build / 'qemu-flash.bin'
assert not output.is_symlink() and (not output.exists() or output.is_file())
output.write_bytes(image)
PY
```

## Run all tests

```sh
export STICKS3_QEMU="$LAB/qemu-build/qemu-system-xtensa"
export STICKS3_QEMU_ROM_DIR="$LAB/qemu-source/pc-bios"
export STICKS3_PROBE_FLASH="$LAB/peripheral-probe-build/qemu-flash.bin"
export STICKS3_QEMU_ARTIFACTS="$LAB/validation/peripherals"
export LD_LIBRARY_PATH="$LAB/qemu-deps/usr/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
python3 "$REPO/experiments/qemu-sticks3/test_peripherals.py"
```

Without `STICKS3_PROBE_FLASH`, the guest-driver test is explicitly skipped; that
is **not** the complete gate. Without `STICKS3_QEMU`, all tests are skipped. Each
fixture owns only temporary Unix sockets, file-backed UART and screenshots.
Guest flash uses QEMU's snapshot overlay; only regular 8MiB files are accepted.

The dotted USB device type needs QEMU's explicit global syntax:

```text
-global driver=misc.esp32c3.usb_serial_jtag,property=chardev,value=cdc
```

The shorthand dotted form misparses the driver name. The test harness already
uses the correct form. It also uses `-accel qtest` only for MMIO tests and normal
TCG for the guest boot; simply providing `-qtest` is not sufficient for virtual
`clock_step` commands.

This pinned QEMU's PPM writer writes padded RGB24 rows at odd widths. The harness
removes only the known per-row padding before comparing/saving valid PPM files.
Artifacts are `portrait.ppm`, `landscape.ppm`, and `stock-idf.ppm`; the full initial
run log is `$LAB/peripheral-suite.log`.

Actual SDK and QEMU compiler builds are authoritative. A local ignored `.clangd`
can adapt the Xtensa flags/newlib include environment for a host IDE; absence of
cached IDE diagnostics is not a build verdict.

## Timing-profiler contribution

[Physical frame profiling](../../docs/frame-profiling.md) adds an opt-in timing-only
codec to the production renderer, bounded host capture, build provenance, and
render/display cost reports for later calibration. It does not patch this
prototype's clock, GDMA or scanout behavior. Historical working/wide captures
measured 4.79fps initially and 13.58fps after the first exact-raster pass. The
latest clean round-2 working/vertical windows measure 17.51fps at Os and 19.82fps
at O2; they are not same-layout A/B comparisons with the older wide results.
The updated [timing specification](../../docs/stick-transport-timing.md) requires
source/mode/recipe-matched evidence rather than a fictional 30fps CPU budget.

`measured_frame_envelopes.h` preserves the clean round-2 source/binary fingerprints,
mode and recipe, with render/display and effective pre-wire p95 candidates. The
shared native/QEMU guest `transport_scenarios.h` explicitly replays these occupancy
inputs without recording, verifies continued >33ms busy frames and late starts,
and leaves USB grants, SPI divider and QEMU CPU clocks unchanged. These modeled
schedules are not measured emulator FPS or exact physical start intervals;
independent percentiles do not form a measured frame. The round-2 physical O2
start p95 is 52,996us, while its effective pre-wire p95 candidate is 35,723us.
Do not apply these historical vertical/native envelopes to new firmware, wide
layouts or voice-load timing. Full production GDMA/board-init/PSRAM remains
an independent, incomplete gate.

Round-3 mouth/mask kernels are compile-/native-parity-tested. Both captures pass occupancy gates, but
clip/label/contact differences preclude a controlled A/B claim. Effective
pre-wire p95s are 28,288/24,199us; latest start p95 is 41,003us. `cachePass`
retains both source/binary fingerprints and `all` feeds the shared
native/QEMU-guest transport checks. `findEnvelope` rejects unknown
hashes/recipes/layouts; actual QEMU FIFO tests separately replay preset packets
for both new build IDs, not measured emulator CPU costs. Do not scale old
envelopes by host benchmark ratios or use them automatically for the new
